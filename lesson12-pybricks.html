The Big Idea

What is Pybricks?

Your hub has firmware on it — the built-in software that makes it a robot brain. LEGO puts their firmware on at the factory, and that's what runs your SPIKE App programs.

Pybricks is different firmware. You install it yourself, and once it's on, the hub runs ordinary Python — the same Python you've been writing all year.

🧱

In Lesson 11

You wrote SPIKE App 3 Python. LEGO's firmware, LEGO's modules, competition-safe.

⚡

In this lesson

You swap the firmware for Pybricks and get a cleaner, faster API built for robots.

🔄

Either way

Same hub, same motors, same you. You can switch back and forth in about two minutes.

Same Robot, Two Languages

“Drive forward 30 cm”

SPIKE App 3 — Lesson 11
import motor_pair from hub import port import runloop async def main(): motor_pair.pair(motor_pair.PAIR_1, port.A, port.B) await motor_pair.move_for_distance( motor_pair.PAIR_1, 300) runloop.run(main())
Pybricks — this lesson
from pybricks.hubs import PrimeHub from pybricks.pupdevices import Motor from pybricks.robotics import DriveBase from pybricks.parameters import Port, Direction hub = PrimeHub() left = Motor(Port.A, Direction.COUNTERCLOCKWISE) right = Motor(Port.B) robot = DriveBase(left, right, wheel_diameter=56, axle_track=112) robot.straight(300)

💡 Notice: no async, no await, no runloop. In Pybricks, robot.straight(300) just drives and waits until it's done. Simple things stay simple — and when you do want two things at once, you'll ask for it on purpose. (That's the multitasking slide, coming up.)

Why Would You Want This?

Four reasons teams switch

🧭 Gyro turns are built in

One line — robot.use_gyro(True) — and every turn measures the real angle instead of counting wheel rotations and hoping the wheels don't slip.

🔀 Real multitasking

Drive forward while the arm lifts. One function call, no tricks. This is the big one for FLL mission runs.

⚡ Uploads are fast

Press F5, the program is on the hub and running in about a second. No app, no copy-paste, no waiting.

🐍 It's just Python

Real functions, real classes, real imports across files. Everything you learned in Lessons 1–10 works the way you'd expect.

Open that folder in VS Code. When it asks whether to install the recommended extensions, say yes — that's the Python extension and Pybricks Runner, which gives you a one-click play button.

Setup — Step 2 of 5

Put Pybricks on the hub

Chrome or Edge only. Safari and Firefox cannot do this — flashing firmware uses a browser feature called Web Bluetooth that only Chrome and Edge support. If the install button is greyed out, this is why.

1

Open code.pybricks.com in Chrome or Edge.

2

Click the gear icon → Install Pybricks firmware → choose SPIKE Prime.

3

Give your hub a name you'll recognize, like bb-hub-1. You'll use it to connect later.

4

Unplug the hub. Then hold down the big round Bluetooth button and — still holding — plug the USB cable back in. Keep holding until the light flashes.

5

Pick the hub in the popup, click Connect, and wait about a minute. Don't unplug it.

Setup — Step 3 of 5

Run your first program

Make sure the hub is on and your computer's Bluetooth is on. Then, from the pybricks-starter folder:

uv run pybricksdev run ble examples/01-hub/hello.py

That program is four lines long and does this:

from pybricks.hubs import PrimeHub from pybricks.parameters import Icon from pybricks.tools import wait hub = PrimeHub() hub.display.icon(Icon.HEART) hub.speaker.beep() wait(1000) hub.display.text("BOT BUDDIES")

❤️ A heart appears and the hub beeps? Your whole setup works. That's the hardest part done.

Setup — Step 4 of 5

Running from VS Code

😀 The easy way — Pybricks Runner

Click the Pybricks icon in the left sidebar, find your hub, press play. That's it.

⌨️ The official way — F5

Open the file you want to run and press F5. Works even if the extension breaks someday.

Don't press the green ▶ button

The green play button in the top-right corner of the editor runs your program on your laptop — where there is no robot. It will do nothing, or throw an error like ModuleNotFoundError.

F5 is the one that talks to the hub. If you ever see an error that mentions pybricks not being found, you almost certainly pressed the wrong button.

Setup — Step 5 of 5

Putting the LEGO firmware back

The hub runs one firmware at a time, so while Pybricks is installed it won't run programs from the LEGO SPIKE App. Your old programs are safe on your computer — the hub just needs LEGO's firmware back to run them. Here's how, any time you want it:

1

Open the LEGO Education SPIKE App (education.lego.com/en-us/downloads/spike-app/software/).

2

Connect your hub with the USB cable.

3

The app notices the hub has non-LEGO firmware and offers to update it. Accept.

4

If it doesn't offer on its own, find the hub/firmware settings and choose to reinstall the hub firmware.

5

Done — it's a normal SPIKE Prime again. To go back to Pybricks later, just repeat Step 2.

🔁 You can bounce back and forth as many times as you like. Nothing wears out.

The Big One for FLL — Part 1 of 2

🔀 Doing two things at once

Normally your program runs one line at a time. Drive forward. Then lift the arm. Then turn. Each one finishes before the next starts.

But on a mission run, seconds matter. Why wait for the robot to stop driving before the arm starts moving? If they don't interfere with each other, they should happen together.

😴 One after the other

robot.straight(500) # 3 seconds arm.run_angle(500, 180) # 2 seconds # total: 5 seconds

⚡ Both at once

await multitask( drive_forward(), raise_arm(), ) # total: 3 seconds

⏱️ Two seconds saved, on one action. Across a whole 2½-minute match, that adds up fast.

The Big One for FLL — Part 2 of 2

How multitasking looks in code

from pybricks.tools import multitask, run_task # Each job becomes an "async def" function. async def drive_forward(): await robot.straight(500) async def raise_arm(): await arm.run_angle(500, 180) async def main(): # Both happen at the SAME TIME instead of one after the other. await multitask(drive_forward(), raise_arm()) run_task(main())

async def

Marks a job that's allowed to pause and let something else run.

multitask(...)

Runs the jobs you give it together, and waits until all of them are done.

run_task(...)

The one line at the bottom that actually starts everything. Like runloop.run() in Lesson 11.
