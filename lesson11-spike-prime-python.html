Setup — Program Slots

Loading code into the hub's slots 🎰

🎰 What are slots?

The hub can hold up to 20 programs at once — slots 0–19. It's the very same grid of squares you see in the SPIKE App.

📌 Pick a slot right from VS Code

Add one special comment at the very top of your file. The extension reads it and uploads to that slot:

# LEGO slot:5 autostart from hub import light_matrix import runloop async def main(): await light_matrix.write("5") runloop.run(main())

The hub's 20 slots (0–19):

Slot 5 now holds your program ✨

▶ How it runs

slot:5 chooses the slot; autostart runs it the moment the upload finishes. Without autostart, press the extension's ▶ button — or on the hub, tap ◀ ▶ to slot 5 and press the center button.

🏆 FLL tip: give each mission its own slot — Mission 1 → slot 1, Mission 2 → slot 2… then just tap through them at the table.

Async & Await — Part 1 of 4

The slow way: do one thing, then just… wait 🐢

You're making breakfast: oatmeal in the microwave 🥣 and toast in the toaster 🍞. Here's the slow way — start the microwave, then stand there staring at it until it dings. Only then start the toaster.

1️⃣ The microwave is heating… and you just stand there watching it 😐
🔔 DING! The oatmeal is done — only NOW can you start the toaster
2️⃣ The toaster is toasting… and you’re still just standing there 😐
🍞 POP! The toast is finally ready
3️⃣ Only now do you set the table — breakfast at the very last second 🐢

🐢 What went wrong?

Nothing else could happen while you waited. The toaster sat cold, the table stayed empty — even though you weren't busy at all. Watch the timer bar: breakfast is ready at the very last second.

🤖 Why robots care

Motors, sounds, and sensors all take real time. If the hub froze completely every time it waited, your robot could never drive and watch a color sensor at the same time.

Async & Await — Part 2 of 4

The smart way: start it, then go be useful ⚡

Same breakfast, same clock. But this time you start the microwave and the toaster, then set the table while both are working. You only come back when something's actually ready.

2️⃣ While they both work away, you go set the table 🍽️

⚡ Same clock, half the time

The microwave still takes exactly as long as before — but the toaster and the table-setting happened during the wait instead of after it. Breakfast lands halfway through the bar.

🔑 The one-sentence version

Async means: start something, and while it's working, go do something else. Come back and check on it when it's done. That's the whole idea!

Async & Await — Part 3 of 4

From breakfast to Python 🍞➡️🐍

Every breakfast step has a matching line of SPIKE code. Same idea, different words.

1Grab the recipe card that says "this one has waiting steps"
➜
async def main():
2Start the microwave — and wait right here for the DING 🔔
➜
await motor.run_for_degrees(port.A, 360, 720)
3Flip the toaster lever and walk away — no waiting needed
➜

4Come back and wait right here for the POP 🍞
➜
await sound.beep(440, 400, 100)
5Actually start making breakfast (nothing happens until you do!)
➜

👀 Spot the pattern: the steps you have to wait for get await. The instant steps don't. Writing the recipe card down isn't the same as cooking — that's why runloop.run() is needed at the bottom.

Async & Await — Part 4 of 4

Why async on the def, and await on the call? 🤔

They're two different jobs — one labels the whole recipe, the other marks one single step.

📋
async def main():

Goes on the whole function. It's a heads-up label: "the steps inside here include some waiting."

Why it's needed: Python has to know before it starts running that this function might pause. Without async, you're not even allowed to write await inside.

🍳 Breakfast version: writing "⏳ has waiting steps" at the top of the recipe card.

✋
await motor.run_for_degrees(…)

Goes on one single step, at the moment you call it. It means: "stop right here until this finishes, then keep going."

Why it's needed: a motor takes real seconds to turn. Without await, Python fires off the command and races to the next line — so the motor barely moves before it's interrupted.

🍳 Breakfast version: "don't touch the oatmeal until the DING."

🤝 They're a package deal

await only ever lives inside an async def. You'll never see one without the other — if a function needs to wait, it must be async.

🚨 Two classic mistakes

❌ Forgot await → the motor twitches and stops.
❌ Forgot async → Python throws a SyntaxError on the await line.

The One New Idea — runloop

The pattern every SPIKE program uses ⏳

SPIKE 3 programs wrap your instructions in a special main function and start it with runloop.run(). The magic word is await — it means "wait for this action to finish before doing the next line."

import runloop import motor from hub import port async def main(): # await = "finish spinning BEFORE moving on" await motor.run_for_degrees(port.A, 360, 720) await runloop.sleep_ms(1000) # pause 1 second runloop.run(main()) # <-- this line starts the program

🔑 Two rules to remember: put your steps inside async def main():, and start it with runloop.run(main()) at the very bottom.

Example — Part 1 of 3

Light matrix display + sound 💡🔊

from hub import light_matrix, sound import runloop async def main(): # scroll a message across the 5x5 await light_matrix.write("Hi!") # show a built-in picture light_matrix.show_image( light_matrix.IMAGE_HAPPY) # beep: freq, milliseconds, volume await sound.beep(440, 400, 100) runloop.run(main())

🟨 The 5×5 light matrix

write() scrolls text. show_image() shows a built-in picture like IMAGE_HAPPY, IMAGE_HEART, or IMAGE_SAD.

🔊 Sound

beep(frequency, duration_ms, volume). Higher frequency = higher pitch. Great for telling you the program actually started!

Notice: write and beep use await (they take time). show_image is instant, so it doesn't need it.

Example — Part 2 of 3

Motors & driving 🚗

import motor, motor_pair, runloop from hub import port async def main(): # spin ONE motor: port, degrees, speed await motor.run_for_degrees(port.C, 360, 720) # pair two wheel motors to drive motor_pair.pair(motor_pair.PAIR_1, port.A, port.B) # drive straight: pair, degrees, steering await motor_pair.move_for_degrees( motor_pair.PAIR_1, 720, 0) runloop.run(main())

⚙️ One motor

run_for_degrees(port, degrees, velocity). Velocity is in degrees per second — bigger = faster.

🚗 Two motors together

First pair() your left & right wheel motors into PAIR_1. Then drive them as one. Steering 0 = straight; negative turns one way, positive the other.

Tip: plug your two drive motors into A and B, and an arm/tool motor into C — then this code just works.

Example — Part 3 of 3

Reading a sensor & reacting 👀

import distance_sensor, runloop from hub import port, light_matrix, sound async def main(): # distance in millimeters (-1 = nothing) mm = distance_sensor.distance(port.D) if mm != -1 and mm < 100: # something is close! light_matrix.show_image( light_matrix.IMAGE_SAD) await sound.beep(880, 300, 100) else: light_matrix.show_image( light_matrix.IMAGE_SMILE) runloop.run(main())

📏 Distance sensor

distance(port) returns how far the nearest object is, in millimeters. It returns -1 when it can't see anything.

🧠 Your Python brain

This is just an if/else from Lesson 3 — but now the robot acts on what it senses. Sensing + deciding = a smart robot.

Other sensors work the same way: color_sensor.color(port) and force_sensor.pressed(port).

The hub reacts:
closer than 100mm → SAD + beep
vs
all clear → SMILE
Bonus Sensor — The Gyro

The hidden superpower: the built-in gyro 🧭

from hub import motion_sensor import runloop async def main(): # call the way we face now "zero" motion_sensor.reset_yaw(0) await runloop.sleep_ms(500) # angles are in DECIdegrees (1/10 deg) yaw, pitch, roll = motion_sensor.tilt_angles() print("yaw =", yaw) # 900 means 90.0 deg if yaw > 900: print("Turned past 90 degrees!") runloop.run(main())

🧭 What is the gyro?

A sensor built inside the hub — no port needed! It measures how the hub is turned and tilted: yaw (spin left/right), pitch, and roll.

🔢 Decidegrees & zeroing

Values come in tenths of a degree — divide by 10. So 900 = 90.0°. reset_yaw(0) sets your current direction as "straight ahead."

🏆 Why FLL teams love it

It's the secret to driving dead straight and making exact turns every run — far more reliable than guessing with time or wheel degrees alone.

Putting It All Together

The complete main.py 📄

import runloop, motor, motor_pair, distance_sensor from hub import port, light_matrix, sound async def main(): # 1. DISPLAY — say hello on the 5x5 await light_matrix.write("Hi!") light_matrix.show_image(light_matrix.IMAGE_HAPPY) # 2. SOUND — a beep so we know it started await sound.beep(440, 400, 100) # 3. MOTOR — spin the arm motor on port C once await motor.run_for_degrees(port.C, 360, 720) # 4. SENSOR — look with the distance sensor, then react mm = distance_sensor.distance(port.D) if mm != -1 and mm < 100: light_matrix.show_image(light_matrix.IMAGE_SAD) await sound.beep(880, 300, 100) else: light_matrix.show_image(light_matrix.IMAGE_SMILE) # 5. DRIVE — pair the wheels (A & B) and go forward motor_pair.pair(motor_pair.PAIR_1, port.A, port.B) await motor_pair.move_for_degrees(motor_pair.PAIR_1, 720, 0) runloop.run(main())

💾 Save this as projects/spike-hello/main.py — display, sound, a motor, a sensor, and driving, all in one program.
